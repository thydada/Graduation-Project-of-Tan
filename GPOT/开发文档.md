# GPOT 快递管理系统开发文档

## 项目概述

GPOT（Graduation Project of Tan）是一个基于Spring Boot和Vue.js开发的快递管理系统，实现了完整的快递寄件、入库、出库、运输、送达等全流程管理功能。系统采用前后端分离架构，支持管理员、员工和普通用户三种角色，每个角色拥有不同的功能权限。

## 技术架构

- **后端**：Spring Boot + JPA + MySQL
- **前端**：Vue.js 3 + Vue Router + Axios
- **数据库**：MySQL

## 系统角色说明

系统包含三种角色：
1. **管理员（Admin）**：系统管理员，拥有最高权限
2. **员工（Employee）**：分为部门A和部门B，负责不同的业务操作
3. **用户（User）**：普通用户，可以寄件和查询包裹

---

## 一、管理员功能

### 1.1 登录认证
- **功能描述**：管理员可以通过用户名和密码登录系统
- **登录方式**：在登录页面选择"管理员"角色，输入用户名和密码进行登录
- **权限说明**：管理员拥有系统的最高管理权限

### 1.2 系统管理
- **功能描述**：管理员可以查看和管理整个系统的运行状态
- **管理范围**：可以查看所有包裹信息、员工信息、用户信息等系统数据

---

## 二、员工功能

员工分为两个部门，每个部门负责不同的业务流程：

### 2.1 部门A员工功能

#### 2.1.1 登录认证
- **功能描述**：部门A员工通过用户名和密码登录系统
- **登录方式**：在登录页面选择"员工"角色，输入用户名和密码进行登录

#### 2.1.2 快递取件审核
- **功能描述**：审核用户寄出的快递是否已成功取件
- **主要操作**：
  - 查看待审核的快递列表（显示收件人信息、收件地址、包裹类型等）
  - 审核快递取件情况，标记为"已取件"或"取件出错"
  - 如果取件出错，可以报告异常件，填写异常类型和异常原因
- **异常类型**：收件人信息错误、收件人未取件、包裹破损、包裹丢失、包裹错发、其他原因

#### 2.1.3 快递送达管理
- **功能描述**：查看分配给自己的运输中包裹，并标记为已送达
- **主要操作**：
  - 查看分配给自己的运输中包裹列表
  - 查看包裹的收件人信息、收件地址等详细信息
  - 确认送达后，将包裹状态更新为"待取件"
- **业务逻辑**：系统会自动将出库的包裹随机分配给部门A的员工进行派送

### 2.2 部门B员工功能

#### 2.2.1 登录认证
- **功能描述**：部门B员工通过用户名和密码登录系统
- **登录方式**：在登录页面选择"员工"角色，输入用户名和密码进行登录

#### 2.2.2 快递入库核验
- **功能描述**：对已取件的快递进行核验并入库
- **主要操作**：
  - 查看待核验的快递列表（显示寄件人信息、寄件地址、包裹类型等）
  - 选择货架和层数（货架1-3为普通货架，货架4为大货架）
  - 核验快递信息，标记为"核验成功"或"核验出错"
  - 核验成功后，系统自动生成取件码，包裹状态更新为"已入库"
  - 如果核验出错，可以报告异常件，填写异常类型和异常原因
- **异常类型**：包裹信息不符、包裹破损、包裹丢失、重量异常、物品违禁、其他原因
- **货架分配**：系统支持手动选择货架和层数，也可以自动分配（根据包裹大小和重量）

#### 2.2.3 快递出库管理
- **功能描述**：将已入库的包裹进行出库操作，分配给派送员工
- **主要操作**：
  - 查看所有已入库的包裹列表
  - 选择需要出库的包裹，执行出库操作
  - 系统自动将包裹分配给部门A的员工进行派送
  - 出库后，包裹状态更新为"运输中"
- **业务逻辑**：出库时系统会随机选择一个部门A的员工作为派送员工

#### 2.2.4 异常件查询
- **功能描述**：查看所有异常件记录，包括取件异常和核验异常
- **主要功能**：
  - 查看异常件列表，包括异常类型、异常原因、报告人、报告时间等信息
  - 查看异常件的处理状态（待处理、处理中、已处理）
  - 查看异常件的处理结果和处理时间
- **统计信息**：显示待处理、处理中、已处理和全部异常件的数量统计

## 三、用户功能

### 3.1 用户注册
- **功能描述**：新用户可以通过注册功能创建账号
- **注册信息**：
  - 用户名（必填，唯一）
  - 密码（必填）
  - 真实姓名（必填）
- **注册流程**：填写注册信息后提交，系统验证用户名是否已存在，注册成功后自动跳转到登录页面

### 3.2 用户登录
- **功能描述**：已注册用户通过用户名和密码登录系统
- **登录方式**：在登录页面选择"用户"角色，输入用户名和密码进行登录

### 3.3 寄件功能（已移除）
- **说明**：普通用户不再支持在线寄件/提交寄件申请。
- **当前用户侧功能**：登录后可在“我的包裹”中查询包裹信息与状态（临时/正式/异常）。

### 3.4 包裹查询
- **功能描述**：用户可以查询自己寄出的所有包裹信息
- **查询方式**：
  - 按快递单号搜索
  - 查看所有包裹列表
- **包裹分类**：
  - **全部包裹**：显示所有包裹（待处理、已完成、异常件）
  - **待处理包裹**：显示正在处理中的包裹（临时包裹）
  - **已完成包裹**：显示已入库的正式包裹
  - **异常件**：显示出现异常的包裹
- **包裹信息**：
  - 快递单号
  - 寄件人和收件人信息
  - 包裹类型、重量、尺寸
  - 包裹状态
  - 创建时间、入库时间
  - 仓库和货架信息（已入库包裹）
- **进度跟踪**：对于待处理包裹，可以查看处理进度（已提交、取件中/完成、核验中/完成）

### 3.5 包裹详情查看
- **功能描述**：用户可以查看包裹的详细信息
- **详情信息**：
  - 基本信息：快递单号、状态、包裹类型、重量、尺寸
  - 寄件人信息：姓名、电话、地址
  - 收件人信息：姓名、电话、地址
  - 时间信息：创建时间、入库时间
  - 存储信息：仓库ID、货架ID、层数（已入库包裹）
  - 异常信息：异常类型、异常原因、处理状态（异常件）

## 四、核心业务流程

### 4.1 寄件流程
1. **包裹进入待入库列表**：包裹信息进入临时表（`package_temp`），状态为"待入库"
2. **员工核验入库（唯一一次审核）**：员工在“快递入库”页面核验快递信息并登记到货架
   - 核验成功：选择货架和层数，生成取件码，包裹转移到正式表，状态为"已入库"
   - 核验失败：报告为异常件
3. **员工出库**：员工将已入库包裹出库，系统随机分配派送员工
4. **员工派送**：派送员工将包裹送达，状态更新为"待取件"

### 4.2 异常处理流程
1. **异常报告**：员工在核验入库过程中发现异常，填写异常类型和原因
2. **异常记录**：系统将异常信息保存到异常件表，从临时表中删除该包裹
3. **异常查询**：员工和管理员可以查看所有异常件记录
4. **异常处理**：管理员或相关员工可以处理异常件，更新处理状态和结果

### 4.3 货架分配机制
- **自动分配**：系统根据包裹大小和重量自动分配货架
  - 大包裹（体积>50000cm³或重量>5kg）：自动分配到货架4（大货架）
  - 普通包裹：自动分配到货架1、2、3（选择使用量最少的货架）
  - 每层容量：普通货架每层10个包裹，大货架每层5个包裹
- **手动分配**：员工可以手动选择货架和层数

## 五、数据库设计

### 5.1 主要数据表
- **admin**：管理员表
- **employee**：员工表（包含部门信息）
- **user**：用户表
- **package**：正式包裹表
- **package_temp**：临时包裹表
- **package_entry**：入库记录表
- **package_outbound**：出库记录表
- **exception_package**：异常件表
- **shelf**：货架表

### 5.2 包裹状态流转
- **待入库** → **已入库** → **运输中** → **待取件** → **已取件**
- 任何环节出现异常，包裹会进入异常件表
